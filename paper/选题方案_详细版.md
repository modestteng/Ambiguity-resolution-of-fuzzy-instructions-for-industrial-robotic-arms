## 方案 A（求稳）：基于 QLoRA 微调 VLM 的工业场景指令歧义检测与消解

### 1. 研究问题

工业机械臂的自然语言控制面临一个核心难题：人类操作员的指令往往是**模糊的**。例如：

| 模糊指令 | 歧义类型 | 场景上下文 |
|----------|---------|-----------|
| "把那个东西放过来" | 指称歧义（哪个东西？放到哪？） | 工位上有螺丝刀、扳手、钳子 |
| "拧紧一下" | 动作歧义（拧什么？拧多紧？） | 装配线上有多个待拧螺栓 |
| "用小的那个" | 属性歧义（多小算小？） | 有 M3、M5、M8 三种规格螺丝 |
| "快点搞定" | 意图歧义（搞定什么任务？） | 当前有焊接和打磨两个待办工序 |
| "别碰那个" | 安全歧义（哪个不能碰？为什么？） | 工位上有高温工件和普通工件 |

现有工作（CLARA、AmbResVLM、Ask-to-Clarify 等）主要聚焦于**家庭/厨房场景**，而工业场景有其独特性：
- 工具种类多且外观相似（各种规格的扳手、螺丝刀）
- 安全约束严格（高温、高压、旋转部件）
- 精度要求高（"放到那边"在家庭场景可以容忍误差，在工业场景不行）
- 操作流程标准化（有 SOP 约束）

### 2. 核心贡献（预期 3 个）

**C1: 工业场景模糊指令歧义分类体系**
- 提出面向工业机械臂的 5 类歧义分类法：
  1. **工具歧义 (Tool Ambiguity)**："用那个扳手" → 工位上有多把扳手
  2. **位置歧义 (Location Ambiguity)**："放到旁边" → 哪个方位、多远
  3. **动作歧义 (Action Ambiguity)**："处理一下" → 焊接？打磨？切割？
  4. **参数歧义 (Parameter Ambiguity)**："拧紧一点" → 扭矩多大
  5. **安全歧义 (Safety Ambiguity)**："把那个拿走" → 是否涉及危险物品
- 参考：AmbiK 的 3 类分类（偏好/常识/安全）、CLARA 的 3 路分类（clear/ambiguous/infeasible）

**C2: QLoRA 微调 VLM 实现端到端歧义检测与消解**
- 在 Qwen2.5-VL-7B-Instruct 上用 QLoRA (4-bit) 微调
- 输入：工业场景图片 + 模糊指令
- 输出结构化 JSON：
  ```json
  {
    "is_ambiguous": true,
    "ambiguity_type": "tool_ambiguity",
    "ambiguity_reason": "工位上存在3把不同规格的扳手，无法确定用户指称的目标",
    "clarifying_question": "请问您需要的是M10的开口扳手、M14的梅花扳手，还是活动扳手？",
    "resolved_action": null
  }
  ```
- 用户回答澄清问题后，再次输入模型生成消解后的精确指令
- 参考：AmbResVLM 的结构化 JSON 输出 + FSM 解码

**C3: 工业场景模糊指令数据集 (IndustrialAmbig)**
- 首个面向工业机械臂的歧义指令数据集
- 规模：3000-5000 样本
- 标注：(指令, 场景描述/图片, 歧义类型, 歧义原因, 澄清问题, 消解后指令)
- 参考：AmbiK 的 2000 样本规模、AmbResVLM 的 1600 样本规模

#### 3.2 模型架构

```
输入层:
  ├─ 图片 → Qwen2.5-VL 视觉编码器 (ViT, frozen)
  └─ 指令文本 → Qwen2.5-VL 文本编码器

骨干网络:
  └─ Qwen2.5-VL-7B-Instruct (4-bit 量化, frozen)
      └─ QLoRA 适配器:
          - r = 16, alpha = 32
          - target_modules: q_proj, k_proj, v_proj, o_proj
          - dropout = 0.05
          - 可训练参数: ~17M (占总参数 0.24%)

输出层:
  └─ 结构化 JSON 生成（通过 prompt 约束输出格式）
      ├─ 歧义检测: is_ambiguous (bool)
      ├─ 歧义分类: ambiguity_type (5类)
      ├─ 歧义原因: ambiguity_reason (自由文本)
      ├─ 澄清问题: clarifying_question (自由文本)
      └─ 消解指令: resolved_action (自由文本, 需要用户回答后生成)
```

## 方案 B（冲2区）：注意力引导的工业指令歧义感知与自适应消解框架

### 1. 研究问题

在方案 A 的基础上，引入一个更深层的研究问题：**VLM 在处理模糊指令时，其内部注意力分布是否能作为歧义的可解释信号？**

直觉很简单：
- 当指令清晰时（"拿起红色的 M10 扳手"），VLM 的视觉注意力应该**聚焦**在目标物体上
- 当指令模糊时（"拿起那个工具"），注意力应该**分散**在多个候选物体上
- 这种注意力的集中/分散程度可以被量化，作为歧义检测的**内在信号**

### 2. 核心贡献（预期 4 个）

**C1: 工业场景模糊指令歧义分类体系**（同方案 A）

**C2: 注意力引导的歧义检测机制 (Attention-Guided Ambiguity Detection, AGAD)**
- 从 Qwen2.5-VL 的中间层提取 text-to-image cross-attention map
- 计算注意力熵 (Attention Entropy) 和注意力分散度 (Attention Dispersion) 作为歧义度量
- 训练一个轻量级歧义预测头（2层 MLP 或小型 CNN）
- 与 CLUE 的区别：
  - CLUE 用 PaliGemma2-3B，我们用更强的 Qwen2.5-VL-7B
  - CLUE 只取第 14 层注意力，我们探索多层注意力融合策略
  - CLUE 面向通用场景，我们针对工业场景做领域适配
  - 我们引入注意力熵作为可解释指标，CLUE 用 CNN 黑箱预测

**C3: 自适应提问策略 (Adaptive Questioning Strategy)**
- 根据注意力分布模式决定澄清问题的类型：
  - 注意力分散在**多个同类物体** → 问属性（"您需要哪种规格的？"）
  - 注意力分散在**多个不同区域** → 问位置（"您指的是左侧还是右侧的？"）
  - 注意力**无明显聚焦** → 问意图（"您想要执行什么操作？"）
  - 注意力聚焦在**危险物品** → 安全确认（"该物品温度较高，确认要拾取吗？"）
- 这是方案 A 中没有的**核心技术创新**

**C4: IndustrialAmbig 数据集**（同方案 A）

#### 3.2 AGAD 模块详细设计

```python
# 伪代码：注意力引导的歧义检测

# Step 1: 提取多层 cross-attention maps
attention_maps = []
for layer_idx in selected_layers:  # 探索哪些层最有效
    attn = model.get_cross_attention(layer_idx)  # [B, H, T_text, T_image]
    attention_maps.append(attn)

# Step 2: 注意力融合
fused_attn = multi_layer_fusion(attention_maps)  # 加权融合或拼接

# Step 3: 计算歧义度量指标
# 3a. 注意力熵 (Attention Entropy)
#     对每个文本 token 的视觉注意力分布计算熵
#     H = -sum(p * log(p))，熵越高 → 越可能是歧义
attn_entropy = -torch.sum(fused_attn * torch.log(fused_attn + 1e-8), dim=-1)
avg_entropy = attn_entropy.mean(dim=-1)  # 平均到 batch 级别

# 3b. 注意力分散度 (Attention Dispersion)
#     衡量注意力是否集中在少数 patch 上
#     Gini coefficient 或 top-k concentration ratio
top_k_ratio = fused_attn.topk(k=10, dim=-1).values.sum(-1) / fused_attn.sum(-1)
dispersion = 1 - top_k_ratio  # 分散度越高 → 越可能是歧义

# Step 4: 歧义预测头 (轻量 MLP)
ambiguity_features = torch.cat([avg_entropy, dispersion, other_features], dim=-1)
ambiguity_prob = ambiguity_head(ambiguity_features)  # 2层 MLP → sigmoid
```

#### 3.3 自适应提问策略

```
注意力分布分析:
  │
  ├─ 模式 1: 多峰注意力，峰值在同类物体上
  │   └─ 检测方法: 对注意力 heatmap 做峰值检测 + 物体类别比对
  │   └─ 提问策略: 询问区分性属性（颜色/尺寸/编号）
  │   └─ 示例: "您需要的是 M10 还是 M14 的扳手？"
  │
  ├─ 模式 2: 注意力分散在不同空间区域
  │   └─ 检测方法: 注意力空间分布的方差分析
  │   └─ 提问策略: 询问空间位置
  │   └─ 示例: "您指的是工位左侧还是右侧的工件？"
  │
  ├─ 模式 3: 注意力均匀分散，无明显聚焦
  │   └─ 检测方法: 注意力熵超过阈值
  │   └─ 提问策略: 询问操作意图
  │   └─ 示例: "请问您需要执行什么操作？焊接还是打磨？"
  │
  └─ 模式 4: 注意力聚焦但涉及安全标记区域
      └─ 检测方法: 注意力峰值 + 安全区域 mask 重叠
      └─ 提问策略: 安全确认
      └─ 示例: "该工件表面温度超过 80°C，确认要裸手拾取吗？"
```

#### 3.4 训练流程（两阶段）

```
Stage 1: 歧义检测微调（AGAD 模块训练）
  ├─ 冻结 Qwen2.5-VL 主干
  ├─ 训练 QLoRA 适配器 + 歧义预测头
  ├─ 损失函数: Binary Cross-Entropy (歧义检测) + Cross-Entropy (5类分类)
  ├─ 数据: IndustrialAmbig 数据集的 (图片, 指令, 歧义标签, 歧义类型)
  └─ 训练量: ~2000 步, ~2-3 小时 (单卡 A100)

Stage 2: 消解能力微调（端到端生成训练）
  ├─ 冻结歧义预测头
  ├─ 继续训练 QLoRA 适配器
  ├─ 损失函数: Language Modeling Loss (生成澄清问题 + 消解指令)
  ├─ 数据: IndustrialAmbig 数据集的完整标注
  └─ 训练量: ~5000 步, ~5-8 小时 (单卡 A100)
```

### 4. 与方案 A 的核心区别

| 维度 | 方案 A | 方案 B |
|------|--------|--------|
| 歧义检测方式 | 端到端生成（让 VLM 直接输出 is_ambiguous） | 注意力信号 + 预测头（可解释的内在信号） |
| 提问策略 | VLM 自由生成（无显式策略控制） | 基于注意力分布模式的自适应策略 |
| 可解释性 | 低（黑箱生成） | 高（可可视化注意力 heatmap） |
| 技术贡献深度 | 工程性（微调+数据集） | 方法论（AGAD 机制 + 自适应策略） |

### 5. 评测体系（方案 B 额外的评测）
